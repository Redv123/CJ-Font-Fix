# CJ Font Fallback Fix

[English](README.md) | [简体中文](README.zh-CN.md)

**CJ 指中文和日文，中文包括简体和繁体。** CJ Font Fallback Fix 是一款 Chrome/Chromium 扩展。

Chrome 在 Linux 中，如果网页没有用 `lang` 声明语言，也没有在 CSS 中调用合适的字体，就可能默认使用 Regular 字体。这个插件能让 Linux Chrome 正确调用粗体，并在 `lang="en-US"` 的网站中调用正确的中文字体。这种问题多见于中文网站，日文网站大多会标记 `lang="ja"`。

对于 macOS 和 Windows，系统本来就能正确调用粗体。插件主要用于缺少 `lang` 标签，或 `lang` 填为 `en-US` 但含有大量 CJK 字符的网站，让浏览器调用正确的 CJK 字体。对于访问不同语言网站的用户，或正在学习日文却也需要访问中文网站的用户，插件会检查网页语言，再调用对应地区的汉字字体。

![Linux Chrome 中的中文网页：左侧由扩展调用正确的中文字体和粗体，右侧为原始显示](docs/images/bold-chinese-before-after.png)

图中是 Linux Chrome 打开的中文网页，`lang` 标为 `en-US`。左侧启用扩展后，浏览器使用了正确的中文字体和粗体；右侧未启用扩展，文字落到了 Regular 字重。

## 工作原理

扩展支持**简体中文、繁体中文和日文**。用户为网站手动选择的语言优先。开启默认的**信任网页标明的中文或日文**后，根元素明确标出的中日文地区语言由浏览器处理；子元素只要自行设置了 `lang`，即使标的是其他语言，也交给浏览器处理。扩展不改动这些元素的字体 CSS。其余情况会抽取长度受限的网页文本，结合浏览器语言检测、假名和简繁汉字线索判断。根元素只有 `lang="zh"` 时，仍需判断简繁；文字线索不足时，就使用**默认中文变体**。文字太少或只有各地区共用的汉字时，判断仍可能不准。

默认的**高级模式**保留网站指定的字体，只在需要时调整顺序。通常，选定字体排在网站指定的字体之后、第一个通用字体（如 `sans-serif`）之前。如果前面有已识别、但地区不符的中日文字体，选定字体会提前到这些地区字体前；网站的西文字体和无法确认地区的字体仍留在前面。字体列表中第一个通用字体是 `serif` 或 `ui-serif` 时使用“宋体”设置，其余情况使用“黑体”设置。下面只示意排列方式：

```text
网站西文字体, 地区未知的网站字体, sans-serif
→ 网站西文字体, 地区未知的网站字体, 选定字体, sans-serif

网站西文字体, 已识别的简体字体, sans-serif  [日文内容]
→ 网站西文字体, 选定日文字体, 已识别的简体字体, sans-serif
```

这些名称不是实际 CSS 字体名，也不代表插件预设了某个平台的字体。开启保留网站字体的选项后，如果网页加载的字体或本机已有的指定字体适合当前语言，通常就不会插入选定字体。网站手动语言设置的优先级高于网页自身的语言声明。

**简单模式**需要手动开启。它只把网页根元素的 `lang` 改为 `zh-CN`、`zh-TW` 或 `ja`，不为各元素注入字体 CSS。浏览器和系统决定具体使用哪款字体，因此设置页中选定的字体不适用于这个模式。简单模式会短暂等待初次由网页脚本生成的内容；确定语言后，或最多两秒后，就停止观察后续变化。

高级模式还有一个默认关闭的**检测明确分隔的中文和日文文本块（实验性）**选项。只有自动判断、根元素没有明确 CJK `lang`，且中文和日文证据都足够多的页面才会启用；手动选择网站语言时不会启用。启用后，证据充分的直接文本片段可以分别使用对应字体，包括独立的纯假名片段，以及只混有已知日文特征汉字的假名片段。它不修改 `lang` 或整页判断，也不会按空格拆分普通句子；无法确定的片段沿用整页结果。某些元素需要临时包裹文本；关闭选项会移除这些包裹元素，但相邻文本节点可能被合并。

## 字体与设置

在**设置 → 字体选择**中，可以预览并分别选择简体、繁体、日文的“黑体”和“宋体”字体。下拉菜单只列出浏览器报告为已安装的字体；默认值从本机可用的地区字体中选择，Linux 上安装了 Noto Sans CJK 时会优先选用。“宋体”选择“与黑体相同”时，会沿用同一语言的“黑体”字体。修改会自动保存到浏览器同步存储。

**保留网站加载的 CJK 字体**与**保留网站指定且本机已安装的 CJK 字体**分别检查网页加载的字体和网页点名的本机字体。开启相应选项后，如果已有字体适合当前语言，扩展不会把选定字体插到它前面；已知地区不符的字体仍可被修正。已安装且可用的仿宋字体在中文内容中也会受到保护，但日文内容需要让日文字体排在仿宋前面。

默认开启的**监视并重新检测动态页面**会在相关内容或语言发生变化时更新高级模式的结果。关闭后，初次得到的整页语言结果保持不变；网页字体加载后仍可能重新检查字体。相同的最终字体列表共用 CSS 规则，避免给每个重复元素写一份内联样式。扩展不会等网页字体全部下载完才开始工作；没有 CJK 文字的页面也不会反复进行完整的语言检测。

弹窗可以为当前网站选择**自动、简体中文、繁体中文、日文或禁用**。网站语言设置按主机名保存，也可以通过设置页的**管理网站语言设置**查看、增加、修改或删除。选“自动”会删除该网站的手动设置，不会存储一个“自动”值。**删除所有网站设置**只清除网站设置；主设置里的**恢复默认设置**不会清除它们。

界面会随浏览器语言自动切换为英文、日文、简体中文或繁体中文，没有单独的语言开关。无法匹配时使用英文。

## 查看运行状态

点击工具栏图标，可以看到 **HTML lang**、网页选择或检测出的语言，以及扩展是否实际介入。“模式”一栏显示“高级 · 字体修正”或“简单 · 仅 lang”。高级模式还显示**已应用字体**（插件实际加入 CSS 的已选字体）、**CSS 干预**和**处理元素**数量。这些字段说明插件做了什么，不等于浏览器最终为每个字形选用了哪款实际字体。简单模式改为显示**应用的 lang**。实验性混排检测找到其他局部语言时，会连同稳定的整页结果一起显示。

图标表示**插件是否在当前页面使用**：高级模式实际处理了字体，或简单模式应用了根元素 `lang` 时，魔导书打开。简单模式即使设置的值与原来相同，也会算作已应用；其他情况下魔导书合上。Chrome 内部页面、Chrome 应用商店及部分浏览器保护页面无法运行此扩展。

## 安装

1. 解压发布版 ZIP。
2. 打开 `chrome://extensions`，开启**开发者模式**。
3. 点击**加载已解压的扩展程序**，选择解压后的目录。
4. 打开扩展的**设置**，检查或调整字体选择。

从源码构建时，运行 `npm ci` 和 `npm run build`，然后加载生成的 `dist` 目录。

## 开发与限制

源码使用 TypeScript、Vite 和 Manifest V3，运行时代码没有第三方依赖。主要模块和运行流程见[架构说明](docs/architecture.md)；已确定的取舍见[设计决策](docs/decisions.md)；浏览器测试方法见[测试说明](docs/testing.md)。

```sh
npm install
npm test
npm run test:sites
npm run build
```

`npm test` 运行本地单元测试。`npm run test:sites` 会在真实 Chromium 中运行本地 SPA 样本和若干在线网站测试；完整网站测试需要联网，也可能受网站变化影响。可选的 `npm run test:corpus` 使用 `CJ_FLORES_DIR` 指向本机的 FLORES-200 数据；语料不会提交到仓库，也不会打包进扩展。准备方法和测试边界见[测试说明](docs/testing.md)。`npm run build` 会先检查 TypeScript，再把扩展构建到 `dist`。

GitHub 使用 [Build and release](.github/workflows/release.yml) 从对应版本的源码生成发布附件。发布前先写好 `docs/releases/v<版本>.md`，流程会使用这份说明，不自动生成更新日志。把版本修改和发布说明提交到 `main` 后，在 Actions 页面选择该流程并从 `main` 运行；它会核对 `package.json` 和 `manifest.json` 的版本，执行 `npm ci`、单元测试、类型检查和构建，最后创建 `v<版本>` 标签及附带 ZIP 的 Release。推送匹配的版本标签也会触发同一流程。不要先手工创建空的 Release；流程会在构建通过后创建。线上网站测试和可选语料测试不在这个发布流程中运行。

扩展无法读取浏览器最终为**每个字形**使用的实际字体，只能根据网页 CSS、字体信息和本机字体可用性作判断。少量共用汉字无法可靠区分地区；实验性混排也不会覆盖所有行内结构。开放式 Shadow DOM 在被发现后可以处理，封闭式 Shadow DOM 无法检查。
